# Требования

Нормативная спецификация утилиты `mangen`, выведенная из `TASK.md`. Каждое требование
описывает наблюдаемое поведение, критерий приемки и артефакт, которым оно проверяется.

Колонка «Проверка» ссылается на артефакты, которые создаются по ходу реализации.
До появления артефакта `tools/check_trace.py --report` печатает текущее покрытие;
строгий режим (`--strict`) становится гейтом сборки на этапе, когда тесты уже есть.

Обозначения:

- `[test: путь::Имя]` — модульный тест (GoogleTest);
- `[e2e: ННН]` — сквозной сценарий с номером из набора `tests/e2e/run_e2e.sh`;
- `[tool: команда]` — цель сборки или статическая проверка;
- `[manual: перед сдачей]` — ручной аудит.

Коды выхода, используемые везде: `0` — успех, `1` — ошибка файловой системы,
нарушение консистентности или провал проверки целостности, `2` — ошибка использования.

## 1. Функциональные требования

| ID | Требование | Критерий приемки | Проверка |
|---|---|---|---|
| **FR-01** | Каноническая форма запуска — `mangen [DIR_PATH] [OPTIONS]`. Дополнительно опции распознаются до позиционного аргумента по соглашению GNU; `--` завершает разбор опций. | `mangen /tmp -e x` и `mangen -e x /tmp` дают одинаковый результат; `mangen -- -dir` трактует `-dir` как путь | `[test: tests/unit/args.cpp::Placement]` |
| **FR-02** | Без `DIR_PATH` манифест строится для текущего каталога. | Запуск внутри каталога-фикстуры дает манифест без префикса каталога | `[e2e: 002]` |
| **FR-03** | Каждая строка манифеста имеет вид `<относительный путь> : <64 hex в верхнем регистре>\n`; разделитель — ровно пробел, двоеточие, пробел. | Побайтовое сравнение с эталонным файлом | `[e2e: 001]`, `[test: tests/unit/manifest.cpp::Format]` |
| **FR-04** | Обход рекурсивный: в каждом каталоге сначала обычные файлы, затем подкаталоги; обе группы отсортированы по имени побайтово. | Совпадает с примером из `TASK.md` (7 строк; `dir_2/file_6.h` раньше `dir_2/dir_3/file_7.txt`) | `[e2e: 001]`, `[test: tests/unit/walk.cpp::Order]` |
| **FR-05** | Хэш — SHA-256, 64 шестнадцатеричных символа в верхнем регистре. | `printf abc \| sha256sum` совпадает со значением для файла, содержащего `abc` | `[test: tests/unit/sha256.cpp]`, `[e2e: 003]` |
| **FR-06** | Ошибка отдельной записи (нет прав, запись исчезла, ошибка чтения) дает сообщение в stderr, обход продолжается, код выхода 1. | Фикстура с `chmod 000` (пропускается при запуске от root) | `[e2e: 011]` |
| **FR-07** | Непригодный `DIR_PATH` (не существует, не каталог, нет прав на чтение) дает сообщение в stderr, код выхода 1, в stdout ничего. | Запуск на `/nonexistent` и на обычном файле | `[e2e: 010]` |
| **FR-08** | `-h` печатает в stdout инструкцию и описание всех опций и завершается с кодом 0; приоритет выше остальных опций. | `mangen -h` дает 0; `mangen -h -e x` дает 0 | `[e2e: 005]`, `[test: tests/unit/args.cpp::HelpWins]` |
| **FR-09** | `-v` печатает сведения о версии в stdout и завершается с кодом 0. | `mangen -v` дает 0 | `[e2e: 006]` |
| **FR-10** | `-v` сообщает git commit hash текущей сборки (полный или сокращенный) с суффиксом `-dirty`, если рабочее дерево на момент сборки было изменено. | Соответствует `^commit: [0-9a-f]{7,40}(-dirty)?$` | `[e2e: 006]`, `[e2e: 007]`, `[test: tests/unit/trace.cpp::VersionHasCommit]` |
| **FR-11** | `-e PATTERN` исключает записи, чье базовое имя целиком совпадает с шаблоном. `.` соответствует ровно одному байту, `*` — нулю и более байт, `\` экранирует следующий байт; любой другой байт — литерал. | Таблица из 40 и более случаев, включая многобайтовые (UTF-8) имена | `[test: tests/unit/pattern.cpp]`, `[e2e: 020..029]` |
| **FR-12** | `-e` и `-F` можно указывать повторно; условия объединяются. | Две опции `-e` исключают оба класса имен | `[e2e: 024]` |
| **FR-13** | `-F NAME` исключает записи, чье базовое имя побайтово равно `NAME`, без метасимволов и без учета локали. | Имя с точкой исключается буквально; отличие в одном байте отменяет совпадение | `[test: tests/unit/pattern.cpp::Literal]`, `[e2e: 025]` |
| **FR-14** | Исключение каталога исключает все его поддерево; каталог при этом не открывается. | Ни каталог, ни его файлы не попадают в манифест | `[e2e: 023]`, `[test: tests/unit/walk.cpp::Prune]` |
| **FR-15** | Символические ссылки внутри дерева не разыменовываются; каналы FIFO, сокеты и устройства пропускаются. | Фикстура со ссылкой и FIFO: записей нет, зависания нет | `[e2e: 014]`, `[test: tests/unit/policy.cpp::SkipNonRegular]` |
| **FR-16** | Если файл изменился во время чтения (размер или mtime отличаются), выдается диагностика и код выхода 1. | Фикстура с растущим файлом; тестовая файловая система меняет mtime между двумя вызовами `fstat` | `[test: tests/unit/walk.cpp::Snapshot]`, `[e2e: 013]` |
| **FR-17** | `--sign` добавляет последней строкой трейлер `# mangen-hmac-sha256: <64 hex в верхнем регистре>`. HMAC покрывает все байты, предшествующие строке трейлера. | Воспроизводимое вычисление проверяется модульным тестом | `[test: tests/unit/manifest.cpp::Sign]` |
| **FR-18** | `--check MANIFEST` (или `-` для стандартного ввода) проверяет трейлер HMAC. Код 0 при совпадении; 1 при расхождении, отсутствии трейлера или повреждении; 2 при ошибке использования. | Подпись, проверка, порча, повторная проверка | `[e2e: 030..034]` |
| **FR-19** | `--verify MANIFEST [DIR_PATH]` пересчитывает хэши файлов и сообщает `missing`, `added`, `changed` и `ok`. Код 0 только при полном совпадении, иначе 1. | Изменение, удаление и добавление файла после подписи | `[e2e: 035..037]` |
| **FR-20** | Ключ HMAC берется из `MANGEN_HMAC_KEY` или из `--key-file FILE`; в командной строке ключ не принимается; одновременная передача двух источников — ошибка использования; пустой ключ — ошибка использования. | `--sign --key-file k` работает; `--sign` без ключа дает 2; оба источника дают 2 | `[e2e: 031]`, `[e2e: 038]`, `[test: tests/unit/args.cpp::KeySources]` |
| **FR-21** | Коды выхода: 0 — успех; 1 — ошибка файловой системы, нарушение консистентности, провал проверки целостности; 2 — ошибка использования (неизвестная опция, лишний аргумент, конфликт опций, пустой шаблон). | Матрица кодов проверяется сквозными сценариями | `[e2e: 060]`, `[e2e: 066]`, `[e2e: 067]` |
| **FR-22** | Манифест и справочная информация (`-h`, `-v`) идут в stdout; вся диагностика идет в stderr с префиксом `mangen: `. | `mangen dir 2>/dev/null` и `mangen /bad 1>/dev/null` | `[e2e: 061]` |
| **FR-23** | Сборка выполняется через CMake с оберткой `make`, цели `all` и `clean`; исполняемый файл появляется как `./mangen` в корне дерева сборки. | `make clean && make && test -x ./mangen` | `[e2e: 070]` |
| **FR-24** | Утилита не порождает внешних процессов и не линкуется со сторонними библиотеками. | `ldd ./mangen` показывает только libc; в исходниках нет `system`, `popen`, `exec*`, `fork` | `[tool: make grep-check]`, `[e2e: 072]` |

## 2. Нефункциональные требования

Категории соответствуют группам ISO/IEC 25010. «Гейт» означает, что нарушение ломает
`make verify`.

### 2.1 Безопасность

| ID | Требование | Критерий приемки | Проверка | Гейт |
|---|---|---|---|---|
| **NFR-SEC-01** | Файлы внутри дерева открываются без разыменования символических ссылок и без доверия к классификации до открытия. | Политика передает `O_NOFOLLOW`; тип файла определяется по `fstat` после открытия | `[test: tests/unit/policy.cpp::Flags]` | да |
| **NFR-SEC-02** | Открытие необычного файла не может заблокировать процесс. | Файлы открываются с `O_NONBLOCK`; фикстура с FIFO завершается за `timeout 5` | `[e2e: 014]` | да |
| **NFR-SEC-03** | Ключ HMAC никогда не передается через аргументы командной строки и никогда не печатается. | Опции для ключа нет; ключ не появляется в выводе `-v` и в сообщениях об ошибках | `[test: tests/unit/args.cpp::NoKeyInArgv]` | да |
| **NFR-SEC-04** | Сравнение MAC выполняется за постоянное время. | `mng_ct_equal` читает каждый байт, без раннего выхода | `[test: tests/unit/util.cpp::CtEqual]` | да |
| **NFR-SEC-05** | Секреты зануляются; страницы памяти с ключом блокируются, если это возможно. | `mng_secure_zero` после использования; отказ `mlock` сообщается и не прерывает работу | `[test: tests/unit/manifest.cpp::KeyZeroized]` | отчет |
| **NFR-SEC-06** | Утилита не порождает дочерних процессов и не вызывает оболочку. | В `src/` нет `system`, `popen`, `fork`, `exec*` | `[tool: make grep-check]` | да |
| **NFR-SEC-07** | Диагностика не раскрывает содержимое файлов, ключи и пути за пределами переданного корня. | Ручной аудит каждого сообщения и тесты формата | `[manual: перед сдачей]` | — |
| **NFR-SEC-08** | В коде нет небезопасных функций работы со строками и вводом: `strcpy`, `strcat`, `strncpy`, `strncat`, `sprintf`, `vsprintf`, `gets`, семейства `scanf`, `alloca`, `mktemp`, `tmpnam`, `atoi`, `atol`, `atoll`. | Сканер запрещенных функций ничего не находит; данные пользователя никогда не занимают позицию строки формата | `[test: tests/unit/security.cpp::NoUnsafeCalls]`, `[tool: make grep-check]` | да |

### 2.2 Надежность

| ID | Требование | Критерий приемки | Проверка | Гейт |
|---|---|---|---|---|
| **NFR-REL-01** | Нет утечек памяти и неопределенного поведения ни в одном тесте. | ASan, UBSan и LSan чисты | `[tool: make test-asan]` | да |
| **NFR-REL-02** | Отказ любого выделения памяти не приводит к падению или утечке. | Перебор отказов: сбой на N-м выделении для каждого N | `[test: tests/unit/ctx_oom.cpp]` | да |
| **NFR-REL-03** | `EINTR` и частичные чтения и записи обрабатываются повтором. | Инъекция ошибок: `read` возвращает один байт, затем `EINTR` | `[test: tests/unit/fs_fake.cpp]` | да |
| **NFR-REL-04** | Ошибка `readdir` отличается от конца каталога. | `errno` обнуляется до вызова и проверяется после `NULL` | `[test: tests/unit/fs_fake.cpp::ReaddirError]` | да |
| **NFR-REL-05** | Ошибка записи (в том числе `ENOSPC` и `EPIPE`) не маскируется успешным кодом выхода. | Запись в `/dev/full` дает код выхода 1 | `[e2e: 012]` | да |

### 2.3 Ресурсы и производительность

| ID | Требование | Критерий приемки | Проверка | Гейт |
|---|---|---|---|---|
| **NFR-RES-01** | Число одновременно открытых дескрипторов пропорционально глубине, а не размеру дерева. | `ulimit -n 64` при дереве глубины 50 завершается с кодом 0 | `[e2e: 040]` | отчет |
| **NFR-RES-02** | Память — O(глубина · длина пути) плюс фиксированный буфер хэширования; файлы никогда не читаются целиком. | RSS ниже 8 MiB при хэшировании файла размером 100 MiB | `[e2e: 041]` | отчет |
| **NFR-PERF-01** | В матчере шаблонов нет катастрофического перебора. | Шаблон из 10 000 байт против имени из 10 000 байт укладывается в 100 мс | `[test: tests/unit/pattern.cpp::NoReDoS]` | да |
| **NFR-PERF-02** | Пропускная способность SHA-256 остается в разумных пределах. | Не менее 50 MiB/s на эталонном файле (значение попадает в отчет) | `[e2e: 042]` | отчет |

| **NFR-DET-02** | Вывод не зависит от локали. | `LC_ALL=C` и `LC_ALL=C.UTF-8` (а также `ru_RU.UTF-8`, если установлена) дают одинаковый вывод | `[e2e: 051]` | да |

| **NFR-PORT-02** | Работает на ext4 и на 9p/v9fs. | Одинаковый вывод для одного и того же дерева в `/tmp` и в каталоге репозитория | `[e2e: 071]` | отчет |
| **NFR-PORT-03** | Не полагается на `d_type` и на стабильность `st_ino`. | В исходниках нет чтения `d_type` и `st_ino` | `[tool: make grep-check]` | да |
| **NFR-PORT-04** | Код не требует конструкций новее C11. | Конфигурация `clang Release c11` собирается и проходит модульные и сквозные тесты | `[tool: make matrix]` | да |

## 3. Сознательно не реализовано

| ID | Не реализуется | Причина |
|---|---|---|
| NG-01 | Асимметричные подписи (Ed25519, GPG) | Требуют сторонней библиотеки, что запрещено для реализации |
| NG-02 | Дерево Меркла, пофайловые подписи | Избыточно: манифест передается целиком, HMAC покрывает все байты |
| NG-03 | Параллельное хэширование (`--jobs`) | Не требуется; усложняет детерминированный порядок |
| NG-04 | `--follow-symlinks` | Противоречит выбранной политике ссылок и увеличивает поверхность атаки |
| NG-05 | Порт на Windows | Задание подразумевает UNIX-утилиты; целевая среда — Linux |
| NG-06 | `-0/--print0` | Не входит в задание; формат нельзя расширять |
| NG-07 | Вывод в JSON или CSV, `--format` | Расширение контракта без запроса |
| NG-08 | Файл конфигурации | Все параметры помещаются в командную строку |
| NG-09 | Программный интерфейс плагинов | Нет потребителя; расширяемость обеспечена точками подмены |
| NG-10 | Локализация сообщений (gettext) | Тексты сообщений — часть проверяемого контракта |
| NG-11 | Режим слежения (`inotify`) | Другая задача: мониторинг, а не снимок |
| NG-12 | Дедупликация жестких ссылок | Нужны стабильные `st_dev` и `st_ino`, ненадежные на 9p |
| NG-13 | Профили SELinux и AppArmor, seccomp | Вне рамок задания; перечислены как направление усиления |
